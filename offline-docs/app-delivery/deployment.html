Deployment

Once the app is fully configured and tested, follow the steps below to publish it to Google Play Store and Apple App Store.

Applies to both apps

These steps apply to both the Customer App and Delivery App — repeat the whole process for each app, using each app's own package name, icon, and store listing.

1. Google Play Store

Prerequisites

  • A Google Play Developer Account (one-time $25 registration fee).
  • Your Flutter app ready for release.
  • Basic comfort with the command line/terminal.
  • Required assets:
    • App icon (512×512 px)
    • Feature graphic (1024×500 px)
    • Screenshots for different devices (Phone, Tablet)
    • Privacy Policy URL — see Privacy Policy / Terms
    • Short description (up to 80 characters)
    • Full description (up to 4000 characters)
    • Promotional video (optional)

Developer Account Setup

  1. Visit Google Play Console.
  2. Choose your account type:
    • Individual developer — additional testing requirements apply.
    • Organization — requires a D-U-N-S Number.
  3. Complete registration: pay the $25 fee, verify your identity, set up a payment profile, provide contact information, and accept the developer agreement.

Note — Organization accounts

Obtaining a D-U-N-S Number can take 1–30 business days. You'll also need to submit business verification documents and organization details.

Version the Release

In pubspec.yaml, the version is written as version_name+version_code:

version: 1.0.0+1  # Format: version_name+version_code
  • version_name (1.0.0) — the public version number shown to users.
  • version_code (1) — an internal number used by Play Store.

Example sequence across releases:

First release:    1.0.0+1
Bug fix update:   1.0.1+2
Feature update:   1.1.0+3
Major update:     2.0.0+4

Warning

For every new release, you must increment version_code (the number after +) by at least 1. Play Console rejects an upload whose version code isn't higher than the last one, even if version_name changed.

Also confirm android/app/src/main/AndroidManifest.xml has your app's display name and icon set:

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <application
        android:label="Your App Name"
        android:icon="@mipmap/ic_launcher">
        <!-- Your app configuration -->
    </application>
</manifest>

Sign the App

Generate an upload keystore (skip if you already have one):

# Mac / Linux
keytool -genkey -v -keystore YOUR-KEYSTORE-FILE.jks -keyalg RSA -keysize 2048 -validity 10000 -alias YOUR-ALIAS

# Windows
keytool -genkey -v -keystore YOUR-KEYSTORE-FILE.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias YOUR-ALIAS

Follow the prompts to set a password and your details, then confirm. Store the keystore file securely and keep backup copies — it cannot be recovered if lost.

Create android/key.properties (never commit this file):

storePassword=<your keystore password>
keyPassword=<your key password>
keyAlias=upload
storeFile=<path to your keystore file>

Android Developer Verification

Once your signing key is generated, Google requires you to register your package name and signing key for developer verification before the app can go live.

Open android/app/build.gradle and confirm it loads key.properties — add this block near the top if it's missing:

def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

Then confirm the signingConfigs block references it:

signingConfigs {
    release {
        keyAlias keystoreProperties['keyAlias']
        keyPassword keystoreProperties['keyPassword']
        storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
        storePassword keystoreProperties['storePassword']
    }
}

And that the release build type uses it:

signingConfig signingConfigs.release

Save the file and sync your project to apply the changes.

Build Your App

flutter build appbundle --release

Optional flags: --obfuscate to protect your code, --split-debug-info for crash reporting.

The signed bundle is written to:

build/app/outputs/bundle/release/app.aab

App Setup — Create App Listing

  1. Go to Play Console and click Create app.
  2. Fill in basic information: app name, default language, app/game category, free/paid status, and declaration of app content.

Testing Setup

Note

Personal developer accounts created after November 13, 2023 must run a closed test with a minimum of 12 testers, opted in for at least 14 consecutive days, and complete an application process before Google grants production access.

TrackPurposeRequirements
Internal testingQuick distribution to trusted testers; builds ready within secondsNone — optional but recommended first step
Closed testingControlled group testing, policy compliance checks, bug fixing, feedbackApp setup complete; 12+ opted-in testers for 14 consecutive days
Open testingPublic testing — anyone can join; app visible on Google PlayProduction access granted
ProductionFull public release, all Play Console featuresSuccessful closed testing + approved production access application

Production Release

  1. Go to Test and release → Production and click Create new release.
  1. Upload the app bundle (.aab) and add a release name and release notes.
  1. Select the countries you want this track to be available in.
  1. Configure a rollout percentage (you can release gradually rather than to 100% of users at once).
  2. Review every section — store listing, content rating, data safety, app content — then submit for review.

Post-Release Tasks

  • Monitor app performance in Play Console.
  • Track user feedback and reviews.
  • Address bug reports promptly.
  • Plan and schedule future updates.
  • Keep policy compliance up to date.

2. Apple App Store

Prerequisites

  • An Apple Developer Program account ($99/year).
  • Your Flutter app ready for release.
  • A Mac with Xcode installed.
  • Required assets:
    • App icon (1024×1024 px)
    • Screenshots for different devices (iPhone, iPad)
    • Privacy Policy URL — see Privacy Policy / Terms
    • App description
    • Keywords
    • Support URL
    • Marketing URL (optional)
  • An App Store Connect account set up.

Developer Account Setup

  1. Visit the Apple Developer Program page.
  2. Enroll in the program: pay the $99 annual fee, complete organization verification, set up a payment profile, and provide contact information.
  3. In App Store Connect: create the app record, set up basic information, and configure app capabilities.

Version the Release

Same version_name+version_code format in pubspec.yaml as Android:

version: 1.0.0+1  # Format: version_name+version_code
  • version_name (1.0.0) — the public version number shown to users.
  • version_code (1) — an internal build number used by the App Store.

Warning

For every new release, you must increment the build number (the value after +) by at least 1.

Generate App Signing Certificate

  1. Open Xcode, go to Xcode → Settings → Accounts, and add your Apple ID.
  2. Create certificates: a Development certificate and a Distribution certificate.
  3. Create provisioning profiles: a Development profile and an App Store profile.

Build the IPA

flutter build ipa --release

Optional flags: --obfuscate to protect your code, --split-debug-info for crash reporting. The resulting archive is written to:

build/ios/ipa/YourApp.ipa

App Store Connect Setup

Create the app record:

  1. Log in to App Store Connect and click My Apps.
  2. Click + to create a new app.
  3. Fill in basic information: app name, Bundle ID, SKU, and user access.

Choose or create a Bundle ID:

  1. In the Apple Developer portal, go to Certificates, Identifiers & Profiles → Identifiers.
  2. Click + to register a new Bundle ID if you don't already have one (format com.companyname.appname — see Package Name).
  3. Select the capabilities your app requires, then register the Bundle ID.
  4. Use this same Bundle ID in both Xcode and App Store Connect.

Tip

Bundle ID creation can also happen automatically via Xcode if you enable automatic signing in your project settings.

Complete App Information:

  • Privacy Policy URL, Support URL, Marketing URL (optional), App Store category, age rating.
  • Pricing and Availability: price tier, available territories, release date.
  • Screenshots: iPhone screenshots (6.5" display), iPad screenshots (if supported), App Preview videos (optional).
  • App description: name (30 characters max), subtitle (30 characters max), keywords (100 characters max), description (4000 characters max), and "What's New in This Version" notes.

App Privacy: enter your privacy policy URL and complete the data-collection questionnaire — declare any data types your app collects and select the matching options.

Pricing and Availability: set your base country, price schedule, and app availability across territories.

Screenshots and previews: upload iPhone and iPad screenshots for each display size Apple requires — only the first 3 appear on the app installation sheet.

App Review Information — required so Apple's reviewers can test the app:

  • Contact information: first name, last name, phone number, email address.
  • Demo account (if login is required): username/email, password, any special instructions.
  • Notes for the review team: app functionality description, special setup instructions, test account details, known issues or clarifications, and beta/sandbox environment details.

Sign, Archive & Submit

  1. Open the ios folder in Xcode.
  2. In the project navigator, select Runner under Targets, go to Signing & Capabilities, and sign in with your Apple Developer account.
  1. Update the version and build number — Xcode's Generated config file under Flutter/Generated shows the current FLUTTER_BUILD_NAME and FLUTTER_BUILD_NUMBER (read-only, generated from pubspec.yaml):
  1. In Build Settings, scroll down to the User-Defined section and update FLUTTER_BUILD_NAME and FLUTTER_BUILD_NUMBER if you need to override them directly:
  1. Select Any iOS Device as the build target.
  1. Go to Product → Archive.
  1. Once the archive completes, proceed with the upload to App Store Connect.
  1. In App Store Connect, select the build you uploaded from Xcode and click Add for Review to submit it.

Warning

Safeguard your signing certificates and provisioning profiles — losing them means regenerating and re-registering test devices. Thoroughly test the release build before submitting, and monitor the review status in App Store Connect.

Post-Release Tasks

  • Monitor app performance.
  • Track user feedback.
  • Address bug reports.
  • Plan future updates.
  • Maintain compliance with App Store guidelines.

Troubleshooting

IssueCheck
Build failsFlutter version, dependency versions, Xcode version, signing configuration, bundle identifier
Upload issuesCertificates, version number, asset validity, bundle size, API compatibility
Review rejectionRead the rejection reason carefully, make the necessary changes, update compliance, and resubmit

Tip

The first deployment usually takes the longest — subsequent updates go faster once certificates, profiles, and the App Store Connect record already exist.
