Deployment

Once the app is fully configured and tested, follow the steps below to publish it to Google Play Store and Apple App Store.

Applies to both apps

These steps apply to both the Customer App and Delivery App — repeat the whole process for each app, using each app's own package name, icon, and store listing.

1. Google Play Store

Prerequisites

  • A Google Play Developer Account (one-time $25 registration fee).
  • Store listing assets: app icon (512×512 px), feature graphic (1024×500 px), and at least 2 phone screenshots (minimum 1920×1080 px, 16:9 ratio).
  • A Privacy Policy URL — see Privacy Policy / Terms.
  • Basic comfort with the command line/terminal.

Version the Release

In pubspec.yaml, the version is written as version_name+version_code, for example:

version: 1.0.0+1

Warning

For every new release, you must increment version_code (the number after +) by at least 1. Play Console rejects an upload whose version code isn't higher than the last one, even if version_name changed.

Sign the App

Generate an upload keystore (skip if you already have one):

keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

Create android/key.properties (never commit this file):

storePassword=<your-store-password>
keyPassword=<your-key-password>
keyAlias=upload
storeFile=<path-to-upload-keystore.jks>

Build the release App Bundle:

flutter build appbundle --release

The signed bundle is written to:

build/app/outputs/bundle/release/app.aab

Store Listing

AssetRequirement
App icon512×512 px PNG, max 1MB
Feature graphic1024×500 px, max 15MB
Phone screenshotsMin 1920×1080 px, 16:9 ratio, at least 2 required

Testing & Release Track

Upload the .aab under Testing → Internal testing first, then progress through Closed testing → Open testing → Production.

Note

Personal developer accounts created after November 13, 2023 must run a closed test with a minimum of 12 testers for 14 consecutive days before Google allows a production release.

2. Apple App Store

Prerequisites

  • An Apple Developer Program account ($99/year).
  • A Mac with Xcode installed.
  • App icon at 1024×1024 px, plus required screenshots for each supported device size.
  • A Privacy Policy URL and an App Store Connect app record already created.

Version the Release

Same version_name+version_code format in pubspec.yaml as Android. For every new release, increment the build number (the value after +) by at least 1.

Build the IPA

flutter build ipa --release

Add --obfuscate --split-debug-info=<dir> to the command if you want the release build obfuscated. The resulting archive is written to:

build/ios/ipa/YourApp.ipa

App Store Connect Setup

  1. Create the app record using your Bundle ID (format com.companyname.appname — see Package Name).
  2. Fill in app information: category, pricing, screenshots, description, keywords, and privacy details.

Sign, Archive & Submit

  1. Open the project in Xcode and confirm your signing team and provisioning profile under Signing & Capabilities.
  2. Archive the build: Product → Archive.
  3. Use the Organizer window to upload the archive to App Store Connect.
  4. In App Store Connect, attach the uploaded build to your release and submit for review.

Warning

Safeguard your signing certificates and provisioning profiles — losing them means regenerating and re-registering test devices. Thoroughly test the release build before submitting, and monitor the review status in App Store Connect.
