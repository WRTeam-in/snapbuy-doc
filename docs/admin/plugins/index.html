Plugins

Menu path: Settings → Plugins

Plugins are paid add-ons that bolt a new capability onto SnapBuy — a courier, a payment gateway — without you touching any code. You upload a zip, enter the purchase code you were given, and the feature appears across the panel.

What is available​

PluginTypeAdds
ShiprocketShippingLive courier rates, pincode serviceability, waybills, labels, pickups and automatic tracking
PayU IndiaPaymentPayU hosted checkout as a payment method, per country

The Available Plugins section of the page lists what you can buy, with a Buy and a Documentation link on each card. Installed plugins appear above it.

SnapBuy works perfectly well with none installed

Nothing in the core panel needs a plugin. With none installed, delivery is priced by your zone rules, orders go out by delivery boy or a manually entered tracking number, and payments use the built-in gateways. A plugin only adds doors; it never removes one.

Installing a plugin​

  1. Buy the plugin and download its zip. The filename looks like snapbuy-plugin-shiprocket-1.0.0.zip.
  2. Go to Settings → Plugins and click Install on its card.
  3. Enter the purchase code you received when buying it.
  4. Upload the zip exactly as downloaded — do not rename or re-zip it.
  5. Click Install.

Installation runs the plugin's own migrations, merges its language strings and registers it. The card then shows its version, status and licence state.

Upload the zip exactly as you received it

Renaming or re-zipping the package changes what the installer reads and the upload is rejected. If your browser unzipped it on download, download it again and keep the archive intact.

The purchase code is checked once, against the licence server

Installation needs outbound HTTPS. A server that blocks it, or a code already used on another domain, fails at this step — see the troubleshooting table below.

The licence​

StateMeaning
ValidVerified at install. Nothing re-checks it, so a working plugin cannot lose its licence on its own.
UnverifiedThe stored purchase code can no longer be read — this happens when APP_KEY is changed. The plugin keeps working; use Re-enter purchase code to confirm it.
InvalidThe licence server rejected the code.
Never regenerate APP_KEY on a live installation

It encrypts the stored purchase code, along with your payment credentials. Changing it leaves every plugin asking for its code again. See Environment Configuration.

Enabling, configuring and removing​

ControlWhat it does
Toggle on the cardEnables or disables the plugin without uninstalling it. A disabled plugin stops contributing its features; your data stays.
SettingsOpens the plugin's own settings form. Only shown when the plugin has one.
UninstallRemoves the plugin. You are then asked what to do with its data.

Where a plugin's settings live​

Plugin typeConfigured at
ShippingSettings → Plugins → the plugin → Settings
PaymentCountries → edit a country → Payment Gateways — credentials are per country, so a payment plugin has no settings page of its own

A payment plugin's Settings page, if you reach it, says exactly that and points you to the country form.

Uninstalling​

You are offered two answers:

ChoiceEffect
Keep its dataThe plugin's code and licence are removed; its tables, settings and records stay. Re-uploading the zip later resumes with history intact.
Remove its dataAlso rolls back the plugin's migrations and deletes its records. Permanent.
Core keeps your history either way

Shipments booked through a courier plugin, and transactions taken through a payment plugin, are recorded on SnapBuy's own tables. Removing a plugin never deletes an order, a parcel's tracking number on the order, or a payment.

The master switch​

PLUGINS_ENABLED in .env turns the whole system off. When it is false the Plugins page says so and no plugin boots, whatever its own toggle says.

PLUGINS_ENABLED=true
Use it to rule plugins out when debugging

If the panel misbehaves straight after installing something, set it to false, clear the cache from Settings → System Updater, and see whether the problem goes with it.

Permissions​

A single permission, manage_plugins, covers installing, configuring, enabling and uninstalling every plugin. See Roles & Permissions.

Grant it narrowly

Whoever holds it can install code that runs on your server and can read payment credentials. Keep it with the people who administer the installation.

Troubleshooting​

SymptomCauseFix
"Plugins are switched off"PLUGINS_ENABLED=false in .envSet it to true and clear the cache
Could not reach the licence serverNo outbound HTTPS from the serverAllow outbound HTTPS, then retry
The licence server did not accept this purchase codeWrong code, or already used on another domainCheck the code on your Envato account
Please upload a valid zip fileThe package was renamed, re-zipped or partly downloadedDownload it again and upload it untouched
Plugin files are missingThe plugin folder was deleted on the serverRe-upload the zip
Not compatible with this core versionThe plugin needs a newer SnapBuyUpdate SnapBuy — see System Updater
Licence shows UnverifiedAPP_KEY changedClick Re-enter purchase code
The plugin's features do not appearIts toggle is off, or the licence is invalidCheck the card on the Plugins page

Checklist​

  • PLUGINS_ENABLED is not set to false
  • Server allows outbound HTTPS
  • Purchase code to hand, zip untouched
  • Plugin installed, enabled, licence valid
  • Its settings filled in — on the plugin page, or on the country for a payment plugin
  • manage_plugins granted only to installation administrators
